# Version 0.1 contract

Browser core: original classic script `src/marginpack.js`, exposing `globalThis.MarginPack` with `exportSnapshot({html, annotations, metadata}) -> Promise<{html, report}>`. DOMParser, XMLSerializer and Web Crypto are available in supported browsers and the Zotero window. Metadata fields: title, url, savedAt; do not include local paths, library IDs or author names unless the sender explicitly provided them. `annotations` is an array in Zotero.Annotations.toJSON format, with id/type/color/position/text/comment/tags. position may also be a JSON string.

Report has `total`, `matched`, `unresolved`, `unsupported` integer counts and per-item `annotations: [{id,type,status,reason}]`, plus `sourceSha256` (original UTF-8 snapshot bytes). Every input item must remain represented. Duplicate or malformed IDs must not cause silent losses. Viewer must display comments and quotes as plain text. Unsupported annotations remain visible. No fuzzy relocation.

Supported location data: CssSelector, CssSelector.refinedBy TextPositionSelector and body TextPositionSelector; verify quote when available before marking matched. Text positions count DOM UTF-16 code units, not normalized strings. Handle Unicode, whitespace, inline tags, overlapping ranges. DOM cleanup must not invalidate original selectors or offsets; resolve before cleanup or keep a safe mapping.

Exported viewer: self-contained HTML, no fetches or external runtime dependencies; original page scripts, event handlers, forms, active content, remote CSS/media and automatic navigation disabled. Use an isolated source document and CSP defense in depth; explicitly handle data: SVG/HTML, srcset, meta refresh, base, object/embed/iframe, javascript URLs and CSS url/import. Keeping textual context takes priority over original page styling. Links may be exposed only as explicit user actions with safe schemes. Show source URL/title/time and hash, annotation statuses and missing resource limitations; no content is silently certified complete.

Zotero plugin: `addon/bootstrap.js`, `addon/manifest.json`. Menu action for one selected HTML snapshot or one parent containing exactly one HTML snapshot. Read via getAnnotations(), Annotations.toJSON(), getFilePathAsync(), File.getContentsAsync(); no direct sqlite, sync, network requests or edits to Zotero items. Invoke core in main window scope. Save dialog uses Zotero.FilePicker or supported module, output writes only after user selects destination. Cancel is clean. Lifecycle inserts and removes owned menus for every existing/new main window. Current upstream stable is Zotero 10.0.7; claim only actually tested compatibility, document older versions as untested.

Tests: original fixtures model upstream standard selector shapes (https://github.com/zotero/reader/blob/master/src/dom/common/lib/selector.ts). Exercise actual generated HTML in Chromium and Firefox when available. Verify isolated export on file:// with no network, comments and injection payloads, range correctness, overlap, Unicode, unmatched/unsupported data, source immutability, keyboard controls and responsive view. No real personal library data.
